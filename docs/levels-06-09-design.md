# PyCoach 레벨 6~9 상세 설계

> 기준 문서: [`curriculum-quality-guide.md`](curriculum-quality-guide.md)
>
> 목표: 레벨 1~5에서 배운 문법을 “작동하는 작은 프로그램의 구조”로 확장한다.

## 1. 전체 흐름

```text
레벨 5 함수 기초
   ↓
레벨 6 좋은 함수 설계
   ↓
레벨 7 안전한 입력과 프로그램 흐름
   ↓
레벨 8 상태를 가진 객체와 클래스
   ↓
레벨 9 여러 파일로 나누어 조립하는 프로그램
```

| 레벨 | 코스 이름 | 핵심 질문 | 권장 문항 수 | 미니 미션 |
| --- | --- | --- | ---: | --- |
| 6 | 함수를 더 잘 설계하기 | 이 작업은 어떤 값들을 받고 무엇을 돌려줘야 할까? | 8 | 학습 기록 요약기 |
| 7 | 안전하게 입력받고 처리하기 | 잘못된 입력이 들어와도 프로그램을 계속 쓸 수 있을까? | 8 | 안전한 숫자 맞히기 |
| 8 | 클래스로 상태 관리하기 | 관련된 데이터와 기능을 어떻게 한 묶음으로 만들까? | 8 | 학습 캐릭터 만들기 |
| 9 | 모듈로 프로그램 나누기 | 이 코드는 어느 파일의 책임일까? | 8 | 가위바위보 프로젝트 분리 |

## 2. 제공 자료에서 얻은 설계 근거

- 강의자료에는 함수·타입 어노테이션·예외 처리·클래스·디자인 패턴과 모듈·표준 라이브러리·날짜와 시간 과제가 있다.
- 모듈 과제는 `mathtools` 패키지를 `basic`, `advanced`로 나누고, 각 파일의 역할과 import 경로를 명확히 하는 구조다.
- 가위바위보 게임은 실행(`main.py`), 입력 검증(`inputs.py`), 상수와 `Enum`(`constants.py`), 출력(`prints.py`), 게임 규칙(`가위바위보게임.py`)을 분리한다.
- 따라서 레벨 9는 임의의 예시보다 이 게임 구조를 점진적으로 읽고 나누는 방식이 적절하다.

## 3. 레벨 6 — 함수를 더 잘 설계하기

### 학습 목표

- 함수의 입력(매개변수), 처리, 출력(`return`)을 분리해 설명할 수 있다.
- 같은 작업을 다른 데이터에도 적용하는 함수를 작성한다.
- 타입 힌트와 기본값이 코드를 읽는 사람에게 주는 정보를 이해한다.
- 긴 코드를 작은 역할의 함수로 나눌 수 있다.

### 문항 구성

| 순서 | 문항 제목 | 새 핵심 | 문제 설계와 채점 기준 |
| ---: | --- | --- | --- |
| 1 | 통과 여부를 돌려주는 함수 | `bool` 반환 | `is_passing(score)`가 70 이상일 때만 `True`를 돌려준다. 69·70·100 숨은 값으로 확인한다. |
| 2 | 기본 인사말 만들기 | 기본 매개변수 | `greet(name, greeting="안녕하세요")`처럼 기본값과 전달값의 차이를 확인한다. 두 호출 결과를 비교한다. |
| 3 | 점수 문장 꾸미기 | 타입 힌트, f 문자열 | `format_score(name: str, score: int) -> str`의 반환 문장을 만든다. 타입 힌트 존재와 다른 이름·점수 테스트를 확인한다. |
| 4 | 목록에서 가장 높은 점수 찾기 | 누적·비교·`return` | `find_best_score(scores)`가 목록을 순회해 최댓값을 돌려준다. 고정된 100을 돌려주지 못하도록 숨은 목록을 사용한다. |
| 5 | 빈 목록 먼저 확인하기 | 가드 조건 | 점수 목록이 비었을 때의 결과를 먼저 정하고, 일반 목록은 평균을 계산한다. “빈 목록에서 나누기” 오류를 설명한다. |
| 6 | 학생 정보를 딕셔너리로 만들기 | 함수가 자료구조 반환 | 이름·점수로 `{"name": ..., "score": ...}`를 돌려준다. 키와 값, 반환값을 확인한다. |
| 7 | 중복 인사 코드 나누기 | 리팩터링 판단 | 같은 인사 코드가 세 곳에 반복된 예시에서 함수로 뽑을 부분을 찾고, `greet` 호출로 바꾼다. 출력보다 함수 호출 구조를 채점한다. |
| 8 | 미니 미션: 학습 기록 요약기 | 함수 조합 | `calculate_average`, `is_passing`, `format_score`를 각각 만들고 호출해 학습자 한 명의 결과를 출력한다. 함수별 숨은 테스트와 전체 출력 모두 확인한다. |

### 개념 설명과 힌트 예시

- 문법 구조는 `입력 → 처리 → return` 형태의 빈 뼈대를 사용한다.
- 힌트 1: “함수 밖에서 바뀌는 값과, 함수 안에서 항상 하는 일을 나눠 보세요.”
- 힌트 2: “판단 결과는 `True` 또는 `False`로 `return`할 수 있어요.”
- 마지막 힌트: “점수와 기준값을 비교한 식 자체가 불리언 값이 됩니다.”
- 해설에서만 함수의 완성 코드와 타입 힌트의 읽는 법을 설명한다.

### 구현 요구사항

- 기존 함수 구조·숨은 호출 테스트를 재사용한다.
- `bool`, 기본 매개변수, 빈 목록 예외 상황을 허용하도록 안전 실행 AST와 피드백을 확장한다.

## 4. 레벨 7 — 안전하게 입력받고 처리하기

### 학습 목표

- `while`로 사용자가 종료하기 전까지 흐름을 반복한다.
- `try/except`로 숫자가 아닌 입력을 친절하게 처리한다.
- `random`, `datetime` 같은 표준 라이브러리를 목적에 맞게 사용한다.
- 무작정 재귀 호출하는 대신, 반복문으로 입력을 다시 받는 이유를 이해한다.

### 문항 구성

| 순서 | 문항 제목 | 새 핵심 | 문제 설계와 채점 기준 |
| ---: | --- | --- | --- |
| 1 | 세 번 세고 멈추기 | `while` 기본 | `count`가 1부터 3까지 출력된 뒤 멈추도록 조건과 갱신 위치를 익힌다. |
| 2 | 종료 문자를 만날 때까지 | 종료 조건 | 입력값이 `quit`이 아닐 때만 반복한다. `quit` 입력에서는 안내 문구가 추가 출력되지 않는지 확인한다. |
| 3 | 안전한 숫자 변환 | `try/except ValueError` | `int(input())`이 실패하면 다시 입력하도록 만든다. `abc`, `12` 순서의 숨은 입력으로 확인한다. |
| 4 | 범위 안의 점수만 받기 | 검증 반복 | 0~100 밖의 점수는 다시 받는다. 자료형 오류와 범위 오류의 피드백을 구분한다. |
| 5 | 컴퓨터의 선택 만들기 | `random.choice` | 제공된 선택 목록에서 하나를 고른다. 채점은 난수 결과가 아니라 “목록에서 선택했는가”와 반환 형태를 확인한다. |
| 6 | 오늘 날짜 표시하기 | `datetime` | 오늘 날짜를 지정 형식으로 보여 주는 함수를 작성한다. 실제 날짜 대신 주입된 날짜 인자를 사용해 테스트를 고정한다. |
| 7 | 남은 학습일 계산하기 | `timedelta` | 두 날짜의 차이를 일수로 계산한다. 날짜 객체와 문자열의 차이를 설명한다. |
| 8 | 미니 미션: 안전한 숫자 맞히기 | 반복·예외·조건 조합 | 정해진 답을 맞힐 때까지 숫자 입력을 받고, 글자 입력·범위 밖 입력·정답을 각각 처리한다. 답은 테스트가 고정하고 난수 게임은 별도 도전으로 둔다. |

### 중요한 설계 결정

- `random` 결과 자체를 정답으로 채점하지 않는다. 테스트 가능한 값은 함수 매개변수로 주입한다.
- 날짜·시간 문제도 현재 시각에 의존하지 않는다. `today` 같은 인자로 테스트 시간을 고정한다.
- `except Exception`처럼 모든 오류를 뭉뚱그려 잡는 방식은 가르치지 않고, 먼저 `ValueError`처럼 예상한 오류를 다룬다.

### 구현 요구사항

- 안전 실행기에 `ast.While`, `ast.Try`, `ast.ExceptHandler`, `ast.Import`, `ast.alias` 지원을 추가한다.
- 표준 라이브러리는 전체 import를 열지 않고 `random`, `datetime`의 필요한 기능만 안전 목록으로 제공한다.
- 반복문에 최대 반복 횟수 또는 실행 시간 제한을 둬 무한 반복을 막는다.

## 5. 레벨 8 — 클래스로 상태 관리하기

### 학습 목표

- 클래스는 데이터와 그 데이터를 다루는 기능을 함께 묶는 설계도임을 설명할 수 있다.
- `__init__`, `self`, 인스턴스 속성, 메서드를 사용한다.
- 서로 다른 객체가 각자의 상태를 따로 유지함을 확인한다.
- 함수로 충분한 상황과 클래스를 쓰면 좋은 상황을 구분한다.

### 문항 구성

| 순서 | 문항 제목 | 새 핵심 | 문제 설계와 채점 기준 |
| ---: | --- | --- | --- |
| 1 | 학생 한 명을 객체로 만들기 | `class`, `__init__` | `Student(name, score)` 객체를 만들고 이름·점수를 속성으로 저장한다. 클래스명·생성자·속성을 확인한다. |
| 2 | 학생 소개 메서드 | 인스턴스 메서드 | `introduce()`가 자신의 이름과 점수를 문장으로 돌려준다. 두 학생 객체로 숨은 테스트를 한다. |
| 3 | 점수 올리기 | 상태 변경 | `add_score(amount)`가 객체 자신의 점수를 바꾼다. `self.score` 변경 전후를 확인한다. |
| 4 | 통과 여부 묻기 | 객체 안의 판단 | `is_passing()`이 객체의 점수를 기준으로 불리언을 돌려준다. 점수 69·70을 테스트한다. |
| 5 | 두 학생은 서로 다르다 | 인스턴스 독립성 | 민수와 영희 객체를 만든 뒤 한 명의 점수만 바꾼다. 클래스 속성과 인스턴스 속성을 혼동하지 않게 한다. |
| 6 | 학습 캐릭터 경험치 | 여러 메서드 | `Learner`의 `study(minutes)`와 `level_up()`을 만든다. 데이터와 행동을 한 묶음으로 다루는 이유를 설명한다. |
| 7 | 함수인가, 클래스인가? | 설계 판단 | “한 번 계산 후 끝나는 평균”과 “점수·이름·변경 기능을 계속 가진 학생”을 비교해 알맞은 구조를 선택한다. |
| 8 | 미니 미션: 학습 캐릭터 만들기 | 클래스 조합 | 이름·경험치·완료 레슨 수를 가진 `Learner` 클래스를 만들고, 학습할 때 상태가 바뀌는 과정을 출력한다. |

### 범위 밖으로 미루는 내용

- 상속, 오버라이딩, 접근 지정자, 복잡한 디자인 패턴은 레벨 8의 필수 범위에 넣지 않는다.
- `Enum`은 가위바위보 확장 코스에서 표준 라이브러리 활용 예시로 다룬다. 클래스 첫 학습에 함께 넣지 않는다.

### 구현 요구사항

- 안전 실행기에 `ast.ClassDef`, `ast.Attribute`, 메서드 호출, 객체 생성 지원이 필요하다.
- 클래스 구조 채점은 클래스 이름, 생성자 매개변수, 속성, 메서드 존재를 확인한다.
- 객체별 독립성은 두 객체를 생성하는 숨은 테스트로 확인한다.

## 6. 레벨 9 — 모듈로 프로그램 나누기

### 학습 목표

- 한 파일 안의 코드에서 입력·규칙·출력·실행 조립 책임을 구분한다.
- 모듈과 패키지, `import`, `__init__.py`, `__name__ == "__main__"`의 역할을 이해한다.
- 순환 import를 피하는 한 방향 의존 구조를 설계한다.
- 여러 파일로 나뉜 프로그램을 실행하고 오류를 찾는다.

### 문항 구성

| 순서 | 문항 제목 | 새 핵심 | 문제 설계와 채점 기준 |
| ---: | --- | --- | --- |
| 1 | 한 파일의 책임 찾기 | 코드 읽기 | 긴 가위바위보 코드에서 입력·규칙·출력·실행 코드를 색으로 구분한다. 실행형보다 선택·분류형 문항이 적합하다. |
| 2 | 파일 이름 정하기 | 모듈 책임 | `get_user_input`, `judge`, `print_result`, `run_game`을 어떤 파일로 보낼지 설계한다. 이유를 한 문장으로 설명한다. |
| 3 | 상수와 규칙 분리하기 | 상수 모듈 | 가위·바위·보 목록과 승패 규칙을 `constants.py` 또는 `rules.py`에 둘 이유를 확인한다. |
| 4 | 필요한 함수만 가져오기 | import 문법 | `from game.rules import judge`와 `import game.rules`의 사용 차이를 짧은 코드로 연습한다. |
| 5 | 실행 시작점 만들기 | `__main__` 가드 | import할 때는 실행되지 않고 직접 실행할 때만 게임이 시작되는 구조를 작성한다. |
| 6 | 패키지의 문 만들기 | `__init__.py` | 외부에 공개할 함수만 패키지 입구에서 노출하는 이유를 설명한다. 수학 도구 패키지의 단순 버전으로 연습한다. |
| 7 | 미니 랩: 가위바위보를 네 파일로 나누기 | 다중 파일 | `main.py`, `inputs.py`, `rules.py`, `prints.py` 탭에 코드를 배치하고 전체 실행한다. 각 파일의 테스트를 따로 통과해야 한다. |
| 8 | 미니 미션: 학습 기록 패키지 | 패키지 조립 | `records/` 안에 계산·표시 모듈을 만들고 `main.py`에서 가져와 실행한다. import 경로와 책임 분리가 채점 대상이다. |

### 가위바위보 자료와의 연결

제공된 게임의 분리 방식을 학습 사례로 사용한다.

```text
main.py             전체 흐름을 조립하고 실행한다.
inputs.py           사용자의 입력을 받고 검증한다.
constants.py         가위·바위·보, 게임 결과처럼 공유하는 값을 둔다.
rules.py             컴퓨터 선택과 승패 판단을 담당한다.
prints.py            화면에 보여 줄 문장을 담당한다.
```

문항에서는 원본 코드를 그대로 정답으로 요구하지 않는다. 파일명과 변수명은 단순화하되, “파일마다 하나의 주된 책임”이라는 원칙을 익히게 한다.

### 구현 요구사항: 다중 파일 실습 화면

레벨 9의 7·8번은 현재 단일 코드 입력창으로 실행하면 안 된다. 다음 기능을 먼저 만든다.

- `main.py`, `inputs.py`, `rules.py`, `prints.py`처럼 파일 탭을 보여 주는 가상 작업공간
- 파일을 추가·선택·초기화할 수 있는 간단한 편집 UI
- 서버의 임시 폴더에서만 실행되는 가상 파일 시스템
- import 가능한 파일·표준 라이브러리를 제한한 안전 실행기
- 파일별 테스트와 전체 실행 테스트를 나눠 보여 주는 결과 화면
- 사용자가 실제 컴퓨터의 파일을 읽거나 쓰지 못하게 하는 격리

레벨 9의 1~6번은 이 기능 전에도 코드 읽기·설계형 문항으로 먼저 제공할 수 있다.

## 7. 구현 우선순위

1. 기준서에 맞춰 레벨 6 문항을 실제 콘텐츠와 채점 규칙으로 구현한다.
2. 레벨 7용 안전 실행기 확장과 무한 반복 방지 장치를 만든다.
3. 클래스 전용 안전 실행·구조 채점기를 만든 뒤 레벨 8을 구현한다.
4. 다중 파일 가상 작업공간을 만든 뒤 레벨 9의 실행형 미니 랩을 구현한다.

이 순서는 콘텐츠만 먼저 넣고 실행되지 않는 문제를 피한다. 레벨 9의 설계형 문항은 앞당길 수 있지만, 다중 파일 실행형 문제는 실습 환경이 준비된 뒤 공개한다.
