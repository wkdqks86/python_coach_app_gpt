# PyCoach 문항 제작·검수 기준서

> 목적: 초보 학습자가 답을 베끼지 않고, 문제를 읽어 이해한 뒤 필요한 문법을 직접 조합하도록 돕는다.

## 1. 이 문서의 역할

- `backend/app/content.py`는 실제 서비스에 표시되는 **문항 내용의 기준**이다.
- 이 문서는 새 레벨과 문항을 만들 때 사용하는 **제작 원칙과 검수표**다.
- 문항의 문구를 바꾸면 이 기준에 맞는지 검수하고, 기준 자체가 바뀌면 이 문서를 먼저 갱신한다.

## 2. PyCoach의 학습 원칙

1. **문제를 먼저 이해한다.** 개념 설명을 열지 않아도 입력·처리·출력 요구사항을 알 수 있어야 한다.
2. **답보다 사고 순서를 돕는다.** 힌트는 다음 한 줄을 생각하게 해야 하며, 완성 답안을 미리 보여 주면 안 된다.
3. **문법을 실제로 쓴다.** 출력만 같다고 통과시키지 않고, 해당 레슨이 가르치는 구조도 확인한다.
4. **다른 값에도 동작하게 한다.** 입력형 문제는 화면에 보이지 않는 추가 입력값으로 재확인한다.
5. **한 레슨에는 한 가지 새 핵심을 둔다.** 이전 문법은 조합하되, 새 문법을 둘 이상 한꺼번에 도입하지 않는다.
6. **실패는 다음 행동으로 연결한다.** 피드백은 잘못된 이유를 쉬운 말로 설명하고, 고칠 한 가지를 제안한다.

## 3. 한 문항의 필수 구성

| 항목 | 작성 기준 |
| --- | --- |
| 제목 | 학습자가 할 일을 알 수 있는 동사형 제목으로 쓴다. 예: `점수에 따라 결과 나누기` |
| 핵심 원리 | 새 문법이 무엇이고 어떻게 동작하는지 1~2문장으로 설명한다. |
| 왜 배우나요? | 실제 프로그램·데이터 처리에서 쓰이는 이유를 생활 언어로 연결한다. |
| 문법 구조 | 현재 문제와 다른 값·이름을 쓴 짧은 뼈대를 제시한다. 현재 문제의 완성 답안과 같으면 안 된다. |
| 문제 | 시작 데이터, 입력 순서, 해야 할 처리, 정확한 출력 형식을 빠짐없이 쓴다. |
| 시작 코드 | 새 문법과 무관한 준비값만 제공한다. 핵심 로직을 미리 완성하지 않는다. |
| 힌트 | 아래 4절의 단계 규칙을 따른다. |
| 해설 | 정답 코드는 힌트와 분리하고, 각 줄의 역할을 설명한다. |
| 채점 | 출력·문법 구조·숨은 테스트 중 필요한 기준을 명시한다. |

## 4. 개념 설명과 힌트 기준

### 4-1. 개념 설명

개념 설명은 다음 네 블록을 유지한다.

1. **핵심 원리**: 새 문법의 뜻
2. **문법 구조**: 다른 예시를 이용한 코드 뼈대
3. **자주 막히는 지점**: 들여쓰기, 자료형, `return`처럼 초보자가 자주 놓치는 한 가지
4. **문제 풀이 순서**: 한국어 단계 → 코드 단계로 옮기는 순서

문법 구조에는 변수 자리나 설명 주석을 남긴다. 문제의 값·함수명·출력 문장을 모두 그대로 채우면 설명이 답안지가 된다.

### 4-2. 힌트 사다리

| 단계 | 역할 | 허용되는 내용 | 피해야 할 내용 |
| --- | --- | --- | --- |
| 힌트 1 | 방향 잡기 | 문제를 입력·처리·출력으로 나누는 질문 | 함수명과 정답 변수명을 모두 제시하기 |
| 힌트 2 | 문법 단서 | 필요한 문법의 모양, 확인할 조건·자료형 | 완성 코드를 한 덩어리로 제시하기 |
| 힌트 3 | 마지막 추론 단서 | 빈칸, 의사코드, 오류 예방 문장 | 제출 가능한 완성 답안 |
| 풀이·해설 | 학습 마무리 | 완성 코드와 줄별 설명 | 힌트 버튼 안에서 바로 노출하기 |

현재 서비스는 세 번째 정적 힌트를 `마지막 힌트`로 바꾸고, 실제 완성 코드는 별도 `풀이·해설 보기`에서 보여 준다. 새 문항도 이 동작을 전제로 작성한다.

## 5. 문제 문장 기준

### 반드시 포함할 정보

- 입력이 있다면 입력 개수·순서·예시 테스트값
- 시작 데이터가 있다면 목록·딕셔너리·변수의 값
- 처리 규칙과 기준값. 예: `70 이상`, `입력값이 yes일 때`
- 출력해야 하는 문장·줄 수·공백·조사
- 사용해야 하는 핵심 문법. 단, 해결 코드 자체는 쓰지 않는다.

### 좋은 문제 문장 예시

> `score`에 75를 저장하세요. `score`가 70 이상일 때만 `통과`를 출력하세요.

### 고쳐야 하는 문제 문장 예시

> 학습 문장을 출력해 보세요.

무엇을 입력하고 어떤 문장을 출력해야 하는지 알 수 없으므로, 문장·데이터·출력 형식을 보완해야 한다.

## 6. 채점 기준

### 6-1. 출력 채점만 사용하는 경우

`print()` 자체를 처음 연습하는 문항처럼, 학습 목표가 정확한 화면 출력인 경우에만 사용한다. 학습자 이름처럼 정답 문자열이 하나가 아닌 경우에는 비어 있지 않은 출력인지 확인할 수 있다.

### 6-2. 문법 구조도 확인하는 경우

변수·조건문·반복문·함수·자료구조 문제는 출력과 함께 아래를 확인한다.

- 필요한 변수 이름 또는 함수 이름이 있는가
- 필요한 문법 노드가 있는가. 예: `if`, `for`, 리스트, 딕셔너리, f 문자열
- 필요한 연산자·내장 함수가 있는가. 예: `>=`, `%`, `len()`, `input()`
- 함수 문제는 매개변수·`return`·반복문 등 함수 내부 구조가 있는가

구조 검사는 “정답과 똑같은 코드”를 강제하기 위한 것이 아니다. 문제에서 배우기로 한 문법을 실제로 사용했는지만 확인한다.

### 6-3. 숨은 테스트

입력값이나 함수 매개변수가 바뀌어도 작동해야 하는 문제에 사용한다.

- 화면에는 대표 입력값만 보여 준다.
- 서버에는 다른 값의 기대 결과를 보관한다.
- 통과하지 못했을 때는 숨은 값을 공개하지 않고, “고정된 결과 대신 입력 변수 사용”처럼 원인 중심 피드백을 준다.

## 7. 피드백 문장 기준

1. 실행 오류와 오답을 구분한다.
2. 한 번에 한 가지 핵심만 안내한다.
3. “틀렸습니다” 대신 원인과 다음 행동을 함께 쓴다.
4. 정답일 때는 잘한 문법을 짚고 다음 문제를 제안한다.

예시:

- 나쁜 피드백: `오답입니다.`
- 좋은 피드백: `조건이 거짓일 때의 결과도 만들 수 있도록 else를 추가해 보세요.`

## 8. 실습 화면과 모바일 기준

- 코드 입력창에서 `Tab`은 다음 버튼으로 이동하지 않고 들여쓰기한다.
- 모바일에는 입력창 도구줄에 `들여쓰기` 버튼을 둔다.
- 실행·채점 중에는 현재 행동을 설명하는 로딩 안내를 표시한다.
- 정답 처리 뒤에는 같은 화면에서 다음 문제로 갈 수 있는 `다음` 버튼을 제공한다.
- 코스에서 문항을 고르면 입력창 위치로 스크롤해, 학습 흐름이 끊기지 않게 한다.

## 9. 레벨별 난이도 상승 규칙

| 구간 | 문항 설계 |
| --- | --- |
| 레벨 1~2 | 한 줄 또는 한 조건. 시작 코드를 많이 제공한다. |
| 레벨 3~5 | 이전 문법 2~3개를 조합한다. 숨은 테스트와 구조 채점을 늘린다. |
| 레벨 6~7 | 함수 설계·입력 검증처럼 처리 순서를 스스로 나누게 한다. |
| 레벨 8 | 객체의 상태와 메서드처럼 여러 줄이 함께 움직이는 구조를 다룬다. |
| 레벨 9 | 파일별 책임과 import 방향을 판단하고, 여러 파일을 조립한다. |

## 10. 새 문항 배포 전 검수표

- [ ] 문제만 읽고 입력·처리·출력을 알 수 있는가?
- [ ] 개념 설명의 코드가 현재 문제의 완성 답안과 다른가?
- [ ] 힌트 3도 제출 가능한 완성 답안이 아닌가?
- [ ] 새 문법은 하나이며, 이전 문법과의 연결이 자연스러운가?
- [ ] 정답 출력뿐 아니라 핵심 문법을 확인하는가?
- [ ] 입력·함수 문제는 다른 값에서도 통과하는가?
- [ ] 틀렸을 때의 피드백이 구체적이고 친절한가?
- [ ] 모바일에서 들여쓰기·실행·채점이 가능한가?
- [ ] 현재 실행기에서 해당 문법을 안전하게 지원하는가?

## 11. 현재 구현 상태와 다음 확장

- 레벨 1~4는 출력 외에도 변수·연산자·조건문·반복문·자료구조 구조를 확인한다.
- 레벨 5는 함수명·매개변수·`return`·반복·조건과 함수 호출 숨은 테스트를 확인한다.
- 레벨 6의 함수 심화는 현재 실행기를 조금 확장하면 구현 가능하다.
- 레벨 7의 `while`, `try/except`, 표준 라이브러리는 안전 실행 규칙 추가가 필요하다.
- 레벨 8의 클래스와 레벨 9의 import·다중 파일은 현재 한 칸짜리 실행기만으로는 충분하지 않다. 콘텐츠를 넣기 전에 전용 실습 기능을 만든다.
